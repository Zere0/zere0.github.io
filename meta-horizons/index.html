V-52: Sharing Module URI Grant → SD Card Read HIGH

RN sharing modules grant URI read permission on SecureFileProvider backed by external-path="/" (entire SD card). Scope defaults to ANY_APP when ?s= parameter is missing.

Requires attacker app as share target or JS execution in RN context to control mediaPath.

V-45: Content Provider Access Token Leak HIGH

TwilightE2EEModule exposes deleteKeyStore(), purgeKeyOnCloud(), resetUserSecret() to any RN JS code. No per-module authorization. Key destruction = permanent data loss.

Attack Flow — V-24+V-51 (OAuth → HTTP Downgrade → WebView):
1. Attacker crafts: oculus://oauth_iab_stitching/callback?destination_url=http://www.meta.com/path
2. MetaWebAuthenticationActivity processes callback → CALLBACK_URI_KEY
3. C049700z extracts destination_url from callback URI
4. SecureWebView.loadUrl(destination_url) — HTTP passes domain filter
5. MITM injects content in authenticated WebView with session cookies

Attack Flow — V-52 (Sharing → SD Card Read):
1. Deep link / JS triggers sharing module (TwilightHorizonSharingModule)
2. Module creates intent with FLAG_GRANT_READ_URI_PERMISSION
3. URI: content://com.oculus.twilight.securefileprovider/...
4. SecureFileProvider config: external-path path="/" (entire SD card)
5. Scope fallback: ANY_APP when ?s= missing → isInScope() returns true
6. Malicious receiving app reads arbitrary external storage files

Attack Flow — V-46 (E2EE Key Destruction):
1. Attacker achieves JS execution in RN context
2. NativeModules.TwilightE2EEModule.deleteKeyStore()
3. E2EE keys permanently destroyed — no recovery
4. OR: createKeyStore({userSecret: "attacker"}) → attacker controls encryption
