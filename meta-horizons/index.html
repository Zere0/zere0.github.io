V-55: No FLAG_SECURE on Sensitive Screens HIGHNEW

Zero instances of FLAG_SECURE across the entire application. All sensitive screens — payment flows, OAuth tokens, account settings, E2EE key management — are screenshotable, screen-recordable, and visible in task switcher thumbnails.

Impact: Malicious screen-capture apps, shoulder surfing in task switcher, and automated screen-recording malware can capture payment details, session tokens, and private messages.

V-56: Access Token in URL Query Parameters MEDIUM-HIGHNEW

AbstractOkTigonService appends OAuth access tokens as URL query parameters instead of Authorization headers. Tokens logged in server access logs, proxy logs, browser history, and Referer headers on navigation.

Pattern: ?access_token=TOKEN in Tigon HTTP client URLs. Affects all GraphQL/REST calls routed through this service.

V-57: ACRA Crash Reporter LogCat Capture MEDIUMNEW

ACRA crash reporting captures LogCat output on crash. Combined with Spotify PKCE flow logging (code_verifier, authorization_code to logcat), a crash during/after OAuth login leaks PKCE secrets in crash reports sent to remote server.

LogCat capture scope: entire application process buffer. Any sensitive data logged before crash is included.

V-58: No Overlay/Tapjacking Protection MEDIUMNEW

Zero instances of filterTouchesWhenObscured=true across all layouts. No runtime FLAG_WINDOW_IS_OBSCURED checks. All Activities — including payment confirmation, consent flows, and account linking — are vulnerable to tapjacking via malicious overlay apps.

Android overlay permission (SYSTEM_ALERT_WINDOW) allows drawing on top of any Activity. Without filterTouchesWhenObscured, touches pass through the overlay to the victim app.

V-60: WebView-to-RN Hermes Dispatch MEDIUMNEW

Hermes bytecode analysis confirms WebView postMessage dispatches to RN native module callbacks handling sensitive operations (OAuth tokens, payment state, user data). If attacker content loads in WebView (via V-24/V-51), crafted messages reach privileged RN handlers.

Chain: V-24 WebView injection → postMessage → Hermes onMessage → NativeModule.invoke(). Confirmed via Hermes disassembly of message routing.

V-45: Content Provider Access Token Leak HIGH → LOW

FamilyAppsUserValuesProvider returns access_token + user_id from MetaSecureTokenStore. Protected by family app signature check.

V-46: E2EE Key Destruction via RN Module HIGH → LOW

TwilightE2EEModule exposes deleteKeyStore(), purgeKeyOnCloud(), resetUserSecret() to RN JS context.

Downgraded: No demonstrated path for external attacker to execute arbitrary JS in the React Native context. RN bridge is not reachable from WebView or deep links without a separate code execution vulnerability.

V-47: Facebook Token Leak to JS MEDIUM → LOW

TwilightFacebook.fetchDataFromFacebookApp returns raw Facebook access_token to RN JS caller.

Downgraded: Same JS execution barrier as V-46. Attacker cannot invoke this module without prior RN code execution.

V-48: Sessionless Payment Mutation MEDIUM → INFO

LoyaltyTopupMutation in sessionless request whitelist.

Downgraded: Sessionless whitelist is a standard server-side design pattern for specific flows. Server-side authorization still applies.

V-52: Sharing Module URI Grant HIGH → LOW

RN sharing modules grant URI read permission on SecureFileProvider backed by external-path="/".

Downgraded: Attacker cannot control the mediaPath parameter without JS execution in RN context. The URI grant alone is insufficient — attacker must control the file path in the sharing intent.

V-50: DoS via DeviceConfig Flip MEDIUM → LOW

Downgraded: Impact limited to denial of service. No confidentiality or integrity impact demonstrated.
